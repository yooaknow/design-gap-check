# 기획자 질문 작성 가이드

기획자가 질문을 읽고 **30초 안에 고를 수 있게** 쓰는 것이 목표다.

## 좋은 질문의 조건

1. **질문 하나에 결정 하나.** "에러 처리와 빈 화면은 어떻게 할까요?"처럼 묶지 않는다.
2. **사용자가 겪는 상황으로 묻는다.** 디자인 용어(빈 상태, 스켈레톤, 토스트)를 쓰지 않는다.
3. **선택지는 2~4개와 "직접 입력".** 실제로 고를 수 있는 안만 넣는다.
4. **선택지마다 사용자가 보게 될 모습을 한 줄로.** 개발이나 디자인 부담이 크게 다르면 함께 적는다.
5. **추천은 하나.** 원칙 코드(H1~H10)와 이유를 한 줄로 쓴다. 근거는 원칙이나 흔한 서비스 사례로 든다.
6. **왜 지금 정해야 하는지 쓴다.** 이 답이 없으면 무엇이 막히는지 한 줄로.

## 형식

```
### Q1. {사용자 상황으로 쓴 질문}
- 관련 화면: {프레임 이름}
- 왜 지금 정해야 하나: {이 답이 없으면 막히는 것}
- A) {선택지}: {사용자가 보게 될 모습}
- B) {선택지}: {사용자가 보게 될 모습}
- C) {선택지}: {사용자가 보게 될 모습}
- 직접 입력
- 추천: B. [H1] {이유 한 줄}
```

## 나쁜 질문과 좋은 질문

**범위가 넓고 선택지가 없는 질문**
- 나쁨: 에러 처리는 어떻게 할까요?
- 좋음: 글을 쓰다가 인터넷이 끊겨 등록에 실패하면, 쓴 내용은 어떻게 할까요? A) 그대로 두고 다시 시도 버튼 B) 임시 저장함에 자동 보관 C) 사라짐

**디자인 용어로 된 질문**
- 나쁨: 빈 상태 UI는 어떻게 할까요?
- 좋음: 처음 가입해서 아직 참여한 모임이 없는 사람이 홈에 들어오면 무엇을 보여줄까요?

**디자이너가 정할 일을 묻는 질문**
- 나쁨: 로딩은 스피너로 할까요, 스켈레톤으로 할까요?
- 이건 기획 질문이 아니다. 디자이너 할 일로 보낸다.

**이미 PRD에 답이 있는 질문**
- PRD에 "최대 10명"이 있는데 "최대 인원은 몇 명인가요?"라고 묻지 않는다. 대신 "10명이 다 찼을 때 어떻게 보여줄까요?"처럼 정해지지 않은 부분만 묻는다.

## 우선순위

위에서부터 먼저 묻는다.

1. **기능이 끝까지 동작하지 않는 빈칸**: 승인제인데 승인하는 화면이 없는 경우처럼, 흐름이 중간에 끊긴다.
2. **데이터나 권한 구조가 달라지는 빈칸**: 저장할지 말지, 누가 볼 수 있는지. 나중에 바꾸면 개발을 다시 해야 한다.
3. **사용자가 자주 마주치는 빈칸**: 결과 없음, 마감, 대기 상태.
4. **드물게 생기는 빈칸**: 삭제된 대상에 링크로 들어온 경우 등. 질문이 10개를 넘으면 "다음에 볼 질문"으로 보낸다.

## 피해야 할 것

- 선택지에 새 기능을 슬쩍 넣기. 꼭 넣어야 하면 "새 기능 필요"라고 표시하고 추천하지 않는다.
- 같은 결정을 화면마다 따로 묻기. 하나로 묶고 관련 화면을 모두 적는다.
- 추천 없이 선택지만 나열하기. 기획자가 판단할 근거가 없어진다.
