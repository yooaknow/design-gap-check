# 화면 상태 체크리스트

시안의 화면마다 **공통 상태**와 **화면 유형별 상태**를 대조한다.
각 항목의 "정해야 할 것"이 PRD에 없으면 기획 질문 후보이고, 정해져 있는데 화면만 없으면 디자인 할 일이다.

## 원칙 코드

질문의 추천 근거와 디자이너 할 일의 근거로 쓴다. 닐슨의 사용성 휴리스틱 10가지를 기준으로 한다.

| 코드 | 원칙 | 이 체크리스트에서의 뜻 |
|---|---|---|
| H1 | 시스템 상태 보여주기 | 지금 무슨 일이 일어나는지(로딩, 처리 중, 완료, 마감) 사용자가 알 수 있어야 한다 |
| H2 | 현실 세계와 맞추기 | 사용자가 쓰는 말과 순서로 보여준다 |
| H3 | 사용자에게 통제권 주기 | 취소, 되돌리기, 나가기가 가능해야 한다 |
| H4 | 일관성 지키기 | 같은 상황은 같은 방식으로 보여준다 |
| H5 | 오류 예방 | 실수하기 전에 막는다 |
| H6 | 기억하지 않아도 알아보게 하기 | 다시 찾을 곳, 최근 기록을 보여준다 |
| H7 | 숙련자를 위한 효율 | 자주 쓰는 사람에게 지름길을 준다 |
| H8 | 꼭 필요한 정보만 보여주기 | 길거나 많은 정보를 정리해 보여준다 |
| H9 | 오류를 알아차리고 복구하게 돕기 | 무엇이 잘못됐는지, 다음에 뭘 하면 되는지 알려준다 |
| H10 | 도움말 제공 | 처음 쓰는 사람에게 안내한다 |

## 공통 상태 (모든 화면)

| 상태 | 정해야 할 것 | 보통 누가 | 원칙 |
|---|---|---|---|
| 로딩 중 | 표시 방식, 오래 걸릴 때 안내 | 디자인 | H1 |
| 불러오기 실패 (네트워크, 서버) | 다시 시도 방법, 문의 경로 | 디자인 | H9 |
| 로그인하지 않은 상태 | 볼 수 있는 범위, 로그인을 요청하는 시점 | 기획 | H3 |
| 권한 없음 | 차단된 사용자, 비공개 대상에 들어왔을 때 | 기획 | H9 |
| 삭제된 대상 | 링크나 알림으로 삭제된 대상에 들어왔을 때 | 기획 | H9 |
| 긴 텍스트 | 최대 글자 수(기획), 말줄임과 줄바꿈(디자인) | 둘 다 | H8 |
| 큰 숫자 | 999+ 같은 표기 규칙 | 디자인 | H8 |
| 이미지 없음, 이미지 로드 실패 | 기본 이미지 | 디자인 | H1 |
| 첫 사용 | 안내나 온보딩이 필요한지 | 기획 | H10 |
| 화면을 나갈 때 | 하던 작업을 저장할지, 확인을 받을지 | 기획 | H3 |

## 화면 유형별 상태

### 목록, 피드

| 상태 | 정해야 할 것 | 보통 누가 | 원칙 |
|---|---|---|---|
| 처음부터 비어 있음 | 안내만 할지, 다음 행동(찾기, 만들기)을 줄지 | 기획 | H1, H10 |
| 필터 결과 없음 | 필터 초기화를 줄지 | 디자인 | H3 |
| 끝까지 내림 | 무한 스크롤인지 페이지인지, 끝 표시 | 기획 | H1 |
| 새로고침 | 당겨서 새로고침, 새 항목 알림 | 디자인 | H1 |
| 기본 정렬 | 정렬 기준과 바꿀 수 있는지 | 기획 | H2 |
| 항목 상태 표시 | 마감, 대기, 종료 같은 상태를 목록에서 보여줄지, 숨길지 | 기획 | H1 |

### 검색

| 상태 | 정해야 할 것 | 보통 누가 | 원칙 |
|---|---|---|---|
| 검색 전 (검색어 없음) | 최근 검색어, 인기 검색어, 기본 목록 중 무엇을 보여줄지 | 기획 | H6 |
| 입력 중 | 자동 완성을 줄지 | 기획 | H7 |
| 결과 없음 | 안내만 할지, 대안(다른 조건, 만들기)을 줄지 | 기획 | H9 |
| 최근 검색어 관리 | 저장 개수, 삭제 방법 | 기획 | H3 |

### 입력 폼 (가입, 글쓰기, 만들기, 수정)

| 상태 | 정해야 할 것 | 보통 누가 | 원칙 |
|---|---|---|---|
| 필수 항목 누락 | 필수 항목 목록(기획), 알려주는 시점과 방식(디자인) | 둘 다 | H5 |
| 형식 오류, 글자 수 초과 | 제한값(기획), 오류 문구와 위치(디자인) | 둘 다 | H5, H9 |
| 제출 중 | 중복 제출 막기 | 디자인 | H1, H5 |
| 제출 성공 | 다음에 이동할 화면, 완료 피드백 | 기획 | H1 |
| 제출 실패 | 입력한 내용을 유지할지 | 기획 | H9 |
| 작성 중 나가기 | 임시 저장할지, 확인 창을 띄울지 | 기획 | H3 |
| 수정 모드 | 만들기와 같은 화면을 쓸지, 수정할 수 없는 항목이 있는지 | 기획 | H4 |

### 상세

| 상태 | 정해야 할 것 | 보통 누가 | 원칙 |
|---|---|---|---|
| 보는 사람에 따라 다름 | 작성자, 참여자, 처음 보는 사람에게 보이는 버튼 차이 | 기획 | H4 |
| 마감, 종료 | 신청이나 구매 버튼을 어떻게 할지 | 기획 | H1 |
| 공유 | 공유했을 때 보이는 정보 | 기획 | H2 |
| 신고, 차단 | 기능이 있는지, 어디서 하는지 | 기획 | H9 |

### 신청, 예약, 결제

|---|---|---|---|

## 접근성 (디자인 할 일로만 분류)

시안에서 눈에 띄는 경우에만 적는다. 정책 결정이 필요 없으므로 기획 질문으로 만들지 않는다.

- 오류나 상태를 색으로만 구분하지 않기 (아이콘이나 문구 함께)
- 글자와 배경의 명도 대비 4.5:1 이상
- 누를 수 있는 영역 44pt 이상
